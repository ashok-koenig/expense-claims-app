# Expense Claims App

A small expense-claims app: a Node/Express JSON API with in-memory storage, and a TypeScript frontend (compiled to plain browser modules) served by the same server. Employees submit claims, see them in a table, and each claim gets a USD equivalent and an approval tier.

- **Backend:** Express 5, layered (routes → controllers → services → repositories)
- **Frontend:** TypeScript in `public/ts/`, compiled by `tsc` to ES modules in `public/js/` (generated, git-ignored); `index.html` and `css/` are served as-is
- **Storage:** in memory. All claims are lost when the server restarts.

## Setup

Requires **Node.js 20 or later**.

```bash
npm install
cp .env.example .env   # optional; only sets PORT
```

`.env` is optional. The only setting is `PORT` (default `3000`). Never commit `.env`.

## Running the app

```bash
npm run dev        # build, then run with nodemon (rebuilds and restarts when src/ or public/ts/ change)
npm start          # build, then run with plain node
npm run build      # compile public/ts/*.ts to public/js/
npm run typecheck  # type-check the frontend without emitting files
npm test           # placeholder; there are no tests yet
```

`dev` and `start` compile the frontend first, so `public/js/` always exists when the server runs.

Then open:

- Frontend: http://localhost:3000
- API: http://localhost:3000/api/claims

The frontend shows a claims table and a "Submit a claim" form. The **Convert** button next to the amount previews the USD equivalent and approval tier before you submit.

## Claim object

| Field | Type | Notes |
|---|---|---|
| `id` | string | UUID, generated by the server |
| `employeeName` | string | required, trimmed |
| `description` | string | required, trimmed |
| `category` | string | `travel`, `meals`, `lodging`, `supplies`, `other` |
| `projectCode` | string \| null | optional free-text project code; trimmed, and blank or omitted is stored as `null` |
| `costCenter` | string \| null | optional free-text cost center; trimmed, and blank or omitted is stored as `null` |
| `notes` | string \| null | optional short note, at most 200 characters; trimmed, and blank or omitted is stored as `null` |
| `amount` | number | positive, at most two decimal places |
| `currency` | string | 3-letter code, stored uppercase (e.g. `EUR`) |
| `amountUSD` | number \| null | **read-only**, derived from `amount` and the rates file; `null` if the currency has no rate |
| `approvalTier` | string \| null | **read-only**, derived from `amountUSD`; see [Approval tiers](#approval-tiers) |
| `expenseDate` | string | `YYYY-MM-DD`, must be a real calendar date |
| `paymentMethod` | string \| null | optional; one of `card`, `cash`, `bank transfer`; `null`, blank or omitted is stored as `null` |
| `status` | string | `submitted` (default), `approved`, `rejected` |

`amountUSD` and `approvalTier` are always computed by the server. If a request includes them, they are ignored, as are any other unknown fields.

## API reference

Base path: `/api`. Requests and responses are JSON.

### Errors

Every error has the same shape:

```json
{ "error": { "message": "Claim nope not found" } }
```

Validation errors (400) add a `details` array with one entry per problem:

```json
{
  "error": {
    "message": "Validation failed",
    "details": [
      { "field": "category", "message": "category must be one of: travel, meals, lodging, supplies, other" },
      { "field": "amount", "message": "amount must have at most two decimal places" }
    ]
  }
}
```

| Status | When |
|---|---|
| 400 | Validation failed, or the body is not valid JSON (`Request body is not valid JSON`) |
| 404 | Unknown claim id, unsupported currency on the convert endpoint, or unknown route |
| 500 | Unexpected server error (`Internal server error`) |

### Validation rules (POST and PUT)

- `employeeName`, `description`: non-empty strings
- `category`: one of `travel`, `meals`, `lodging`, `supplies`, `other`
- `projectCode`: optional; a string if present (surrounding whitespace is trimmed; `null`, blank or omitted all mean "no project code")
- `costCenter`: optional; a string if present (surrounding whitespace is trimmed; `null`, blank or omitted all mean "no cost center")
- `notes`: optional; a string of at most 200 characters (after trimming) if present; `null`, blank or omitted all mean "no notes"
- `amount`: a JSON **number** (not a string), greater than 0, at most two decimal places
- `currency`: exactly 3 letters; it does not have to be in the rates file
- `expenseDate`: `YYYY-MM-DD` and a real date (`2026-02-30` is rejected)
- `paymentMethod`: optional; one of `card`, `cash`, `bank transfer` if present (`null`, blank or omitted all mean "no payment method")
- `status`: optional; one of `submitted`, `approved`, `rejected`

### `GET /api/claims`

List all claims.

```bash
curl http://localhost:3000/api/claims
```

`200 OK`

```json
[
  {
    "id": "3538e2a0-f9cb-4d99-93bd-b5afb722ffb5",
    "employeeName": "Ann",
    "description": "Hotel",
    "category": "lodging",
    "projectCode": "PRJ-42",
    "costCenter": "CC-1001",
    "notes": "Conference stay",
    "amount": 250,
    "currency": "EUR",
    "amountUSD": 271.74,
    "approvalTier": "manager",
    "expenseDate": "2026-10-01",
    "paymentMethod": "card",
    "status": "submitted"
  }
]
```

Returns `[]` when there are no claims.

### `GET /api/claims/:id`

Get one claim.

```bash
curl http://localhost:3000/api/claims/3538e2a0-f9cb-4d99-93bd-b5afb722ffb5
```

`200 OK` returns the claim object shown above.
`404 Not Found` if the id is unknown:

```json
{ "error": { "message": "Claim nope not found" } }
```

### `POST /api/claims`

Submit a claim. `status` is optional and defaults to `submitted`.

```bash
curl -X POST http://localhost:3000/api/claims \
  -H "Content-Type: application/json" \
  -d '{
    "employeeName": "Ann",
    "description": "Hotel",
    "category": "lodging",
    "projectCode": "PRJ-42",
    "costCenter": "CC-1001",
    "notes": "Conference stay",
    "amount": 250,
    "currency": "eur",
    "expenseDate": "2026-10-01",
    "paymentMethod": "card"
  }'
```

`201 Created`

```json
{
  "id": "3538e2a0-f9cb-4d99-93bd-b5afb722ffb5",
  "employeeName": "Ann",
  "description": "Hotel",
  "category": "lodging",
  "projectCode": "PRJ-42",
  "costCenter": "CC-1001",
  "notes": "Conference stay",
  "amount": 250,
  "currency": "EUR",
  "amountUSD": 271.74,
  "approvalTier": "manager",
  "expenseDate": "2026-10-01",
  "paymentMethod": "card",
  "status": "submitted"

  "amount": 1500,
  "currency": "JPY",
  "amountUSD": null,
  "approvalTier": null,
  "expenseDate": "2026-10-02",
  "paymentMethod": null,
  "status": "submitted"
}
```

### `PUT /api/claims/:id`

Replace a claim's editable fields. It takes the same body and rules as `POST`, so all required fields must be sent. If `status` is omitted, the existing status is kept. `projectCode`, `costCenter` and `notes` are optional, but because `PUT` replaces the claim, omitting any of them clears its existing value. `id` never changes. `amountUSD` and `approvalTier` are recomputed from the new amount and currency.

```bash
curl -X PUT http://localhost:3000/api/claims/3538e2a0-f9cb-4d99-93bd-b5afb722ffb5 \
  -H "Content-Type: application/json" \
  -d '{
    "employeeName": "Ann",
    "description": "Hotel",
    "category": "lodging",
    "projectCode": "PRJ-42",
    "costCenter": "CC-1001",
    "notes": "Conference stay",
    "amount": 600,
    "currency": "EUR",
    "expenseDate": "2026-10-01",
    "paymentMethod": "card",
    "status": "approved"
  }'
```

`200 OK`

```json
{
  "id": "3538e2a0-f9cb-4d99-93bd-b5afb722ffb5",
  "employeeName": "Ann",
  "description": "Hotel",
  "category": "lodging",
  "projectCode": "PRJ-42",
  "costCenter": "CC-1001",
  "notes": "Conference stay",
  "amount": 600,
  "currency": "EUR",
  "amountUSD": 652.17,
  "approvalTier": "finance",
  "expenseDate": "2026-10-01",
  "paymentMethod": "card",
  "status": "approved"
}
```

`400` on validation failure, `404` if the id is unknown.

### `DELETE /api/claims/:id`

```bash
curl -X DELETE http://localhost:3000/api/claims/3538e2a0-f9cb-4d99-93bd-b5afb722ffb5
```

`204 No Content` with an empty body. `404` if the id is unknown (so deleting twice returns 404 the second time).

### `GET /api/rates/convert`

Convert an amount to USD using `data/exchange-rates.json`, and report the approval tier it would get.

| Query parameter | Rules |
|---|---|
| `amount` | required; positive number, at most two decimal places |
| `currency` | required; 3 letters, case-insensitive |

```bash
curl "http://localhost:3000/api/rates/convert?amount=250&currency=EUR"
```

`200 OK`

```json
{
  "amount": 250,
  "currency": "EUR",
  "rate": 0.92,
  "amountUSD": 271.74,
  "approvalTier": "manager"
}
```

`rate` is units of the currency per 1 USD, and `amountUSD` is `amount / rate` rounded to two decimals.

`404 Not Found` when the currency is not in the rates file:

```json
{
  "error": {
    "message": "Currency JPY is not supported. Supported currencies: USD, EUR, GBP, INR, SGD"
  }
}
```

`400 Bad Request` with `details` when `amount` or `currency` is missing or invalid.

## Exchange rates

Rates live in `data/exchange-rates.json`, expressed as units of each currency per 1 USD:

```json
{
  "base": "USD",
  "rates": { "USD": 1, "EUR": 0.92, "GBP": 0.79, "INR": 83.2, "SGD": 1.34 }
}
```

The file is read on every request, so edits take effect without restarting the server. The bundled rates are illustrative placeholders; replace them with current ones. To support another currency, add it to `rates`.

## Approval tiers

Each claim's `approvalTier` is derived from its `amountUSD`, rounded to two decimals:

| Tier | `amountUSD` |
|---|---|
| `auto` | under 100 |
| `manager` | 100 up to, but not including, 500 |
| `finance` | 500 and above |
| `null` | no USD amount (currency not in the rates file) |

Boundaries: 99.99 → `auto`, 100 → `manager`, 499.99 → `manager`, 500 → `finance`.

Notes:

- The tier is computed on the server when a claim is submitted and again when it is updated. Clients cannot set it.
- The thresholds are defined only in `src/models/claim.model.js`. The frontend just displays the tier the API returns.
- The tier does not change `status`; `auto` does not mean auto-approved.
- A `null` tier means the claim could not be tiered, so it should not be treated as `auto`.
